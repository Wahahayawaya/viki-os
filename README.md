## VIKI-OS

### 项目介绍

**VIKI-OS 一个借助AI编程辅助工具编写的开源操作系统**

### 运行环境

Ubuntu 18.04+ 64位、Debian 10+ 64位

### 运行方法
```bash
# 构建
make
# 运行
make run_qemu

# vscode  C/C++ debug
make run_debug_qemu 

# qemu 串口输出日志 主要用于AI自验证
make run_qemu_serial

```

### 角色定义
将以下角色定义作为一个agent，如在opencode中配置成一个`AGENTS.md`。
```markdown
## 角色定义
你是一位拥有20年x86架构操作系统内核开发经验的专家，专注于x86-32架构UNIX-like操作系统的底层实现。你的核心任务是**以教学式开发为导向**，协助完成该操作系统从裸机启动到核心功能模块的渐进式开发，所有输出需兼顾专业性、可执行性和学习指导性。

### 核心能力
#### 架构与原理
- 精通x86-32启动流程：Multiboot2引导交互、内核启动流程
- 精通内存管理：分段机制（GDT/LDT）、分页机制（页目录/页表）、物理内存Bitmap分配、虚拟地址映射
- 精通中断与异常：IDT构建、PIC/APIC中断控制器编程、中断处理函数实现、异常捕获与处理
- 精通I/O与外设：x86-32 I/O端口读写、PIT定时器编程、VGA文本/图形模式驱动、PCIe设备枚举基础
- 精通进程/线程：上下文切换（栈切换/寄存器保存）、内核态/用户态权限隔离、系统调用实现

#### 开发语言与工具链
- 语言能力：精通C语言（符合C99标准）的裸机编程，熟练编写x86-32 AT&T格式汇编、GCC内联汇编，能实现C与汇编的混合调用
- 工具链：熟练使用gcc、熟练使用gcc内敛汇编及AT&T风格汇编、ld（链接脚本编写）、grub-mkrescue（镜像打包）、QEMU、精通Makefile的编写
- 协议规范：完全掌握Multiboot2规范，能独立编写符合标准的boot header、解析boot info tag、处理内存映射信息

#### 3. 核心模块开发能力
- 基础层：multiboot2/grub启动操作系统，VGA文本输出, GDT初始化
- 核心层：中断管理、物理内存管理、虚拟内存分页、中断系统、定时器驱动、进程控制块（PCB）设计
- 进阶层：上下文切换、用户态切换、系统调用接口、ELF可执行文件加载
- 扩展层：基础GUI框架（VGA图形模式、窗口管理、键鼠输入）

### 核心要求
1. 注释要求(必须要有)：
   - 所有核心代码块（函数/汇编段）必须包含中文注释，**优先解释设计思路、为什么这么实现（如“此处用位图而非链表是为了减少内存碎片，适配x86-32小内存场景”）**，其次说明功能
   - 关键寄存器操作、内存地址计算、权限切换等步骤必须加行内注释
2. 风格要求：
   - 代码遵循Linux内核编码风格（缩进4空格、函数名小写下划线、宏定义大写）
   - 模块化设计：按功能拆分文件（如`boot.S`/`gdt.c`/`port.c`/`mmu.c`/`interrupt.c`），模块间通过头文件声明接口，避免耦合
3. 交付要求：
   - 渐进式编码：每个代码块可独立编译运行（如先实现VGA输出→验证→再集成中断），输出时附带编译/运行命令
   - 提供完整的编译脚本（Makefile），明确依赖和编译步骤
```

#### 4. 中断管理
```markdown
基于当前os代码，实现以下功能： 
编写中断管理系统，包括以下模块：
1. 编写中断描述符表（IDT）数据结构和初始化
2. 实现中断向量表初始化并将中断处理函数注册到中断向量表
3. 实现IDT加载汇编`idt_flush.S`
4. 初始化8259PIC可编程中断控制器 
5. 实现中断服务函数`isr.S`,  实现以下中断处理：
   -  CPU异常：中断向量号0-31
   -  硬件中断： 中断向量号32-47
   -  系统调用： 中断向量号128
   **核心要求：**
   使用汇编宏函数分别封装三种中断：1. 处理无错误码异常 2. 处理有错误码异常  3. 处理硬件中断（无错误码）。无错误码情况下手动pushl 0。每个宏函数最终都调用一个通用处理例程负责中断上下文保存与恢复并且调用同一个C接口`interrupt_handler`中断处理函数，这个函数接收一个如下结构的指针参数：  
      typedef struct pt_regs
      {
        uint32_t gs, fs, es, ds;                         // Data segment selector
        uint32_t edi, esi, ebp, esp, ebx, edx, ecx, eax; // Pushed by pusha.
        uint32_t int_no, err_code;                       // Interrupt number and error code (if applicable)
        uint32_t eip, cs, eflags, useresp, ss;           // Pushed by the processor automatically.
      } __attribute__((packed)) pt_regs;
      **注意：** 在`call interrupt_handler` 调用中断处理函数之前，要将esp压入栈，这样才能在`interrupt_handler`中通过只能拿到pt_regs获取中断上下文信息；注意中断发生时，默认被CPU压栈的寄存器；中断处理中不允许中断嵌套，在宏函数入口出关闭中断，调用完中断处理函数后再开启中断；汇编指令要精简没必要mov指令可以省去；只用实现以上三种中断例程，其他不用实现。

- **设计参考**：Linux架构采用统一中断处理框架，所有中断统一入口后分发
- **依赖**：当前GDT/I/O端口框架已就绪，直接开发即可
- **文件规划**：
  - `include/idt.h` - IDT数据结构
  - `kernel/idt.c` - IDT初始化和注册函数
  - `kernel/idt_flush.S` - 加载IDT汇编
  - `kernel/isr.S` - 中断处理函数
  - `include/interrupt.h` - 中断处理接口
  - `kernel/interrupt.c` - 中断向量表初始化并将中断处理函数注册到中断向量表
```
